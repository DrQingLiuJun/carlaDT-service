# CARLA DT Console — approved design

The user approved the mixed approach and implementation in this standalone directory. Eight persistent top-navigation pages: overview (default), scene, driving/sensors, twin telemetry, algorithms, recordings/replay, official examples, resources. Desktop 1920×1080 with laptop compaction, pagination instead of page scrolling. User overrides: QV blue, QP orange, obstacles red, reference green; Source Han Sans Chinese + Arial Latin; all text >=10pt (13.333 CSS px), compact, polished, no redundant status repetition. Map has pointer zoom, drag, fit and actual fullscreen.

Backend owns sessions, recorders, actor ownership, example processes and resource collection; browser is a client. Three controlled-object modes are distinct from C0/C1/C2 algorithm variants. No simulated numbers labeled live. Recorded P4 data is available without CARLA, explicitly labeled replay; CPU/GPU/disk remain actual host observations. CARLA actions require an explicit connected live source. Reset means independent navigation to starts and parking, not teleportation. One clock owner and one controller per actor. Existing algorithm files remain untouched.

Ruling: new project uses React/TypeScript/Vite and FastAPI; no existing web stack was present. User delegated implementation. Host CARLA is 0.9.13-dirty, Python bridge uses existing matching Python3.8 environment; example catalog is 0.9.16 and mismatches must be visible/blocked. Raw native examples use managed processes, key examples have browser-native equivalents. Unsupported sensor/window embedding is labeled rather than faked. No cloud publication: local-machine control and exact local output directory requested.
