# CARLA DT Console Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline. User has already requested implementation of the approved design; no new approval gate. New standalone repository is isolated from the existing algorithm project.

**Goal:** Deliver an operational local console with eight pages, real recording/resource services, historical P4 playback and a version-aware native CARLA bridge.

**Architecture:** React dashboard consumes HTTP + WebSocket updates. FastAPI owns configuration, historical sessions, recorder files and bounded example processes. Matching CARLA interpreter runs a JSON-lines worker, isolating native API versions and world clock ownership.

**Tech Stack:** React19, TypeScript, Vite6, Recharts, Lucide, FastAPI, psutil, CARLA via existing Python3.8.

**Spec:** ../specs/2026-11-09-console-design.md

## Global Constraints
- No edits to dt_dynamic_nav; backend reads its trajectories, models and sources.
- All visible text including SVG/chart/canvas labels >=10pt, local Source Han Sans and Arial.
- QV blue, QP orange, obstacle red, QR green.
- No default CARLA mutations; explicitly labeled recorded playback until connect.
- No telemetry fabrication; live errors derived from matching frame states only.
- Reset is navigation, never set_transform; no destruction of unrelated actors.

## Review Focus
- Offline actions cannot be mistaken for CARLA writes; source and timestamps explicit.
- Dangerous example args, path traversal and duplicate controller launches rejected.
- Connection loss/keyboard focus loss releases input; native actors cleaned by owner.
- UI fits 1920×1080 and 1536×864 without clipped cards or text below minimum.
- Wrong CARLA example/client versions are detected, not silently combined.
