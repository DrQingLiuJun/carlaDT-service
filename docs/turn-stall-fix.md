# HAUT 自车弯道停滞诊断与修复

现场为归位过程中 HAUT 自车与障碍车 2 追尾挤碰：中心约 (-13.32,7.44) 和 (-12.70,7.61)，两车长度均约 4.8 m，车身严重重叠。自车下发 throttle=0 / brake=0.5，传感器持续报告与 Tesla 的接触，累计超过四万条。因此本次现场停滞不能据此归因于发动机有油门而车轮空转；双方均在官方 BasicAgent 障碍检测后制动。

另一处独立问题是路径允许达到物理最大转角，转向曲线反解会在满舵附近得到趋近零的允许速度。UE4 本机 `WheeledVehicleMovementComponent4W.h` 明确标注 SteeringCurve 为 km/h，cpp 通过 KmHToCmS 转换；最终实现保持 km/h，未采用排查期间曾考虑的 m/s 转换。

修复：

- 规划最大曲率使用实际最大转角对应曲率的 98%，给跟踪留出余量。窄弯仍进行车身与曲率检查，不强制给不可行轨迹一个非零速度。
- 车辆避碰使用当前参考路径的前向进度、两车朝向投影后的车身尺寸与制动距离，取代 HAUT 修补拓扑处按原生车道编号判断车辆的 BasicAgent 分支。沿参考路径的前车会减速/制动，后车及相邻车道车辆不会把前车误堵死。红灯检查继续使用 BasicAgent。
- 状态增加 target_speed_kmh、corner_speed_kmh、following_brake，便于区分主动跟车停车与动力不足。
- 碰撞事件缓存限为最近 256 条，避免持续接触导致 WebSocket 数据无限增长。

HAUT 的四个轮胎半径约 56.6–61.2 cm，与 Tesla 的 37 cm 不同，但来自车辆蓝图/网格尺度的参数差异不等于使用不同物理引擎。本修复保留原轮胎、传动、质量与 45° 前轮最大转角，没有通过增大扭矩或取消碰撞来掩盖卡滞。

实测使用保存的三车场景，全程 CARLA 物理执行。修复后完整行驶任务完成，随后三车导航归位完成，两阶段自车碰撞事件均为 0，归位后速度为 0。原始采样见 runtime/turn-fix-verification.json；运行阶段约 30.3 s 墙钟，归位阶段约 21.6 s 墙钟，仿真定步长时间与墙钟不同。
